TRANSPARÊNCIA POR PADRÃO

O que os números dizem.

Uma medição útil precisa mostrar também os seus limites.

01 / AMOSTRA

Os mesmos nomes para todos

Todos os servidores recebem o mesmo conjunto A/AAAA. A ordem dos servidores e consultas é embaralhada por blocos, com semente registrada no JSON. Um servidor por vez reduz competição provocada pelo próprio teste.

O padrão usa 30 domínios como ponto de partida, não como uma amostra universal da web. Importe um HAR do seu navegador para aproximar o teste da sua rotina.

02 / CACHE

Primeira passagem ≠ cache vazio

A primeira passagem mede os nomes ainda não consultados pelo teste. O provedor pode já tê-los em cache. As outras passagens medem repetições, sem garantia de permanência em cache.

O programa consulta diretamente cada IP selecionado. Se ele for um intermediário local, como 127.0.0.53, o teste inclui esse serviço e seu possível cache. Não é possível esvaziar o cache de um DNS público. Serviços do mesmo provedor também podem compartilhar cache. Não geramos subdomínios aleatórios fingindo medir consultas positivas sem cache.

03 / RANKING

Velocidade junto com confiabilidade

Índice = 50% da média de custo da primeira passagem + 50% da média de custo das repetições. Cada falha custa no mínimo o timeout escolhido. As fases mantêm peso igual mesmo com mais repetições.

Mediana e P95 usam respostas válidas; falhas aparecem separadas. NXDOMAIN, SERVFAIL, recusa e endereços de bloqueio não ganham vantagem por responder rápido. NOERROR sem o tipo solicitado (NODATA) é válido, mas não comprova conectividade.

04 / TRANSPORTES

Clássico, HTTPS e TLS

DNS clássico usa UDP e recorre a TCP se a resposta for truncada. DoH negocia HTTP/2, com possibilidade de HTTP/1.1 registrada no relatório. DoT usa TLS com validação de certificado.

Conexões criptografadas são reaproveitadas por faixa de concorrência. As sondagens iniciais incluem a abertura; são exibidas separadamente do ranking. Reconexões durante o teste continuam contando. O IP selecionado é fixado também no DoH, preservando SNI e validação TLS.

05 / INTERPRETAÇÃO

Não existe um vencedor universal

Repita em horários diferentes e com a rede sem downloads intensos. Diferenças pequenas, poucas amostras e mudanças de rota não sustentam uma conclusão definitiva. Não calculamos significância estatística.

O DNS pode influenciar o direcionamento de CDNs, mas este teste não mede throughput, qualidade de vídeo, latência de jogos ou tempo de página. Provedores com políticas de bloqueio têm finalidades diferentes.

06 / AUDITORIA

Dados abertos para conferir

O JSON contém configuração, semente, IPs, consultas, respostas, TTL, falhas e tempos de lote. O CSV contém uma linha por consulta. O bit AD informado pelo resolvedor é registrado; não fazemos validação DNSSEC independente.

Servidores sem resposta na sondagem ficam visíveis como indisponíveis e não recebem ranking. Resultados interrompidos são parciais. As consultas são enviadas aos resolvedores selecionados; não há telemetria.
